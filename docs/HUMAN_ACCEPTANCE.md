## 1. 启动和基础界面

1. Xcode 打开 `Msgbox.xcodeproj`，选择 Msgbox / My Mac，⌘R；也可打开 `build-release/Build/Products/Release/Msgbox.app`。先退出其他 Msgbox 实例，避免多个实例各显示一个图标。
2. 期待：启动即显示“聊天未读 · Msgbox”列表窗口，同时有一个聊天气泡菜单栏图标，没有 Msgbox Dock 图标，不主动弹权限提示。关闭窗口后可继续使用菜单栏；Finder 重新打开 Msgbox 会再次显示列表。若正在用 Xcode 调试旧进程，先 ⌘. 停止，再 ⌘R。
3. 点击图标，期待微信、QQ、Telegram 图标和名称；已运行但没授权时显示“需要辅助功能权限”，未运行或未安装分别显示对应状态。
4. 连续展开/收起 20 次，在系统浅色/深色下查看：内容无截断、按钮可见、状态不残留，VoiceOver 能读出应用/状态/按钮用途。物理屏幕布局、深色与辅助功能体验仍需你确认。

## 2. 主动授予最小权限（需要你手动点击）

1. 在 Popover 中读完用途说明，点击“打开辅助功能设置…”。
2. 在系统设置 → 隐私与安全性 → 辅助功能，用 `+` 添加你实际运行的 Msgbox.app 并开启；若需要鉴权，由你自己输入系统凭证。不要给终端、Codex 或其他应用全局授权来替代 Msgbox 授权。
3. 返回列表点刷新。期待不再显示“需要辅助功能权限”；若出现未知，按第 3 节记录即可，不能按无未读通过。
4. 本地 ad-hoc 签名或重新构建/换路径后可能需要重新添加对应构建。不要关闭 SIP 或修改 TCC 数据库。

## 3. 分别验收三个真实应用

对微信 4.1.13、QQ 7.0.1、Telegram 7.3.3 各执行一次，使用你愿意测试的真实会话；不要把消息内容复制到日志：

1. 确认该应用设置已允许 Dock 未读角标。清空可见未读，记录 Dock 外观和 Msgbox 状态。成功读取空字符串/0 或系统明确返回 noValue 时应为“0 条未读（无角标）”；若系统不支持该属性，允许安全降级为“未知”，但此项兼容性不通过。
2. 请其他设备或联系人发一条测试消息；保留未读。3–5 秒后（或点刷新），期待列表数字/“有未读”与 Dock 一致，有未读的应用排到前方。菜单栏及列表合计应为三个数字角标的总和（如 12、3、7 → 22）；存在圆点、99+、读取失败或无权限时，显示已知数加 `+` 或 `?`，不将未知当作零。
3. 读完该条消息，期待未读标记消失；若系统返回 noValue，应显示 0；不支持角标属性或读取失败仍为未知，记录为限制，不要判为读取成功。
4. 从菜单栏点击该行，期待切换到对应聊天应用；分别测试普通窗口、隐藏窗口和最小化窗口。不恢复时记下真实行为，界面应提示手动恢复限制。
5. 自行退出该应用，15 秒内查看“未运行”（有权限时通常 3 秒）；主动点该行后应启动一份实例。重新运行后刷新应显示当前状态而非退出前旧数值。
6. 不必为了测试“未安装”卸载真实应用，该分支已用模型测试；可在干净测试账户/机器以后验证安装识别。

## 4. 异常和长期运行

- 在系统设置中撤销 Msgbox 辅助功能权限，期待下一次刷新显示无权限且旧未读数字移除；列表仍可打开应用。再授权后刷新恢复，必要时退出并重开实际构建。
- 物理睡眠/屏幕关闭约 1 分钟，唤醒后打开 Popover，期待自动恢复刷新，无忙等待或旧状态覆盖。模拟生命周期测试已经通过，不能替代这一步。
- 开启权限并完成真实角标检查后，退出 Msgbox，执行 README 的 Release 测量命令，在三分钟内不操作其界面；看 `logs/idle-metrics.json` 的 CPU、RSS 和 sockets，并与本次无权限基线比较。
- 另做至少一晚空闲、反复消息变化和物理睡眠；观察活动监视器 CPU/内存/能耗是否持续增长。当前仅短时无权限路径有测量，不能证明长期稳定性或真实功耗。
- 如需更强离线证据，可用现有系统/本机防火墙工具观察 Msgbox（不安装额外软件或改系统权限），并在断网后重复列表和打开已有应用测试。聊天应用自身联网不属于 Msgbox 连接。
